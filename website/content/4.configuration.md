# Configuration

Configure package-owned behavior under `contentMermaid` in `nuxt.config.ts`. Mermaid's own diagram schema remains Mermaid's contract; this page documents only the settings this module owns.

First separate two configuration boundaries: `contentMermaid` controls application defaults for the module and built-in renderer, while page `config`, component `config`, and Mermaid fence frontmatter configure the diagram itself. `toolbar` and `expand` are package-owned UI behavior, not Mermaid `config`.

```ts
export default defineNuxtConfig({
  contentMermaid: {
    loader: { lazy: true },
    theme: { light: 'default', dark: 'dark' },
  },
})
```

## General

`enabled` is Module Activation: Nuxt reads it while the module starts. It is not a public runtime setting. All remaining serializable options can also be supplied through `runtimeConfig.public.contentMermaid`; that transport accepts strict pure data only and resolves to a one-time snapshot when the application initializes.

::callout{variant="warning" title="Reload the application after changing runtime configuration"}
Each Nuxt application instance creates one immutable snapshot from `runtimeConfig.public.contentMermaid`. Mutating the original object at runtime does not reinitialize Mermaid; recreate or reload the application to apply new settings.
::

Package-owned layers use property-presence merging: an absent property falls back, while a present `false`, `null`, `0`, empty string, empty array, or non-object value replaces the lower value.

### Configuration sources

| Source | Scope | Precedence and overrides | Limits |
| --- | --- | --- | --- |
| `contentMermaid` | Nuxt setup and application defaults | Can be overridden by `runtimeConfig.public.contentMermaid` | `enabled` is setup-only; all other values must be serializable data |
| `runtimeConfig.public.contentMermaid` | Runtime settings for the Nuxt application | Overrides module defaults through property-presence merging | Does not accept `enabled`; accepts strict pure data only and creates one snapshot |
| Content page `config` | Mermaid diagrams on one page | Merges with Runtime Mermaid Config | Must be declared in the collection schema and contain pure data only |
| `<Mermaid :config="...">` | One Vue component instance | Merges with Runtime Mermaid Config | May use supported client-only Direct Config capabilities; cannot be supplied with `pageConfig` |
| Mermaid fence frontmatter or directive | One diagram's source configuration | Interpreted according to Mermaid's own rules | Not part of this module's runtime options |

Page `config` and component `config` are mutually exclusive component sources; they are not two layers that can be passed together and override each other. A single diagram can separately override project toolbar defaults through fence `toolbar` or component `toolbar`.

### Module activation and debugging

| Option | Type | Default | Purpose and limits |
| --- | --- | --- | --- |
| `enabled` | `boolean` | `true` | Enables the module, Markdown transformation, and runtime integration during Nuxt setup; it cannot be placed in public runtime configuration. |
| `debug` | `boolean` | `false` | Uses debug-friendly Mermaid error defaults and reports render failures with more detail. |

## Loading and Mermaid initialization

| Option | Type | Default | Purpose and limits |
| --- | --- | --- | --- |
| `loader.lazy` | `boolean` or `{ threshold?: number }` | `true` | Delays initial rendering until the diagram enters the viewport. Set `false` to render on mount. |
| `loader.lazy.threshold` | `number` | `0.1` | `IntersectionObserver` visibility threshold for lazy rendering. |
| `loader.init` | pure-data Mermaid configuration | see below | Project-level Mermaid initialization data; functions and other client-only capabilities are not accepted. |

The `loader.init` baseline is:

```ts
{
  startOnLoad: false,
  theme: 'default',
  fontFamily: 'Arial, sans-serif, 微軟正黑體',
  securityLevel: 'strict',
}
```

Unless explicitly set in `loader.init`, `debug: false` resolves `logLevel: 5` and `suppressErrorRendering: true`; `debug: true` resolves `logLevel: 1` and `suppressErrorRendering: false`. Explicit values always win.

## Theme

| Option | Type | Default | Purpose and limits |
| --- | --- | --- | --- |
| `theme.light` | Mermaid theme name | `'default'` | Theme selected by light color mode or the reserved manual `'light'` strategy. |
| `theme.dark` | Mermaid theme name | `'dark'` | Theme selected by dark color mode or the reserved manual `'dark'` strategy. |
| `theme.useColorModeTheme` | `boolean` | omitted | Deprecated compatibility key; it has no effect. |

Use [Themes and Styling](/advanced/themes-and-styling) for manual theme control, theme precedence, color-mode coexistence, and CSS hooks.

## Custom components

| Option | Type | Default | Purpose and limits |
| --- | --- | --- | --- |
| `components.renderer` | `string` | omitted | Name of an application component that may replace the built-in renderer. |
| `components.spinner` | `string` | omitted | Name of an application loading component supplied to the built-in renderer and a resolved custom renderer. |
| `components.error` | `string` | omitted | Name of an error component for built-in Mermaid render failures. |

Component names resolve from files under `~/components`. A missing or failed renderer candidate returns to the built-in renderer; a successfully resolved custom renderer owns its own loading and error experience. See [Custom Rendering](/advanced/custom-rendering).

A missing `components.spinner` records a diagnostic and falls back to the package spinner. `components.error` applies only to the built-in renderer and is not injected into a successfully resolved custom renderer.

## Toolbar

| Option | Type | Default | Purpose and limits |
| --- | --- | --- | --- |
| `toolbar.title` | `string` | `'mermaid'` | Default toolbar title; it is not Mermaid `title` metadata. |
| `toolbar.fontSize` | `string` or `number` | `'14px'` | Toolbar text size; a numeric value is treated as pixels. |
| `toolbar.fullscreenToolbarScale` | `number` | `1.25` | Multiplier for toolbar text and icons while fullscreen. |
| `toolbar.buttons.copy` | `boolean` | `true` | Shows the copy-source control. |
| `toolbar.buttons.fullscreen` | `boolean` | `true` | Shows the fullscreen control when the browser supports it. |
| `toolbar.buttons.expand` | `boolean` | `true` | Shows the expand-overlay control. |
| `toolbar.labels.copy` | `string` | `'Copy'` | Copy control label. |
| `toolbar.labels.copied` | `string` | `'Copied'` | Copy-success label. |
| `toolbar.labels.copyFailed` | `string` | `'Copy failed'` | Copy-failure label. |
| `toolbar.labels.expand` | `string` | `'Expand diagram'` | Label for opening the expand overlay. |
| `toolbar.labels.collapse` | `string` | `'Collapse diagram'` | Label for leaving the expanded state. |
| `toolbar.labels.minimize` | `string` | `'Minimize diagram'` | Expand-overlay close label. |
| `toolbar.labels.enterFullscreen` | `string` | `'Enter fullscreen'` | Label for entering browser fullscreen. |
| `toolbar.labels.exitFullscreen` | `string` | `'Exit fullscreen'` | Label for leaving browser fullscreen. |
| `toolbar.labels.zoomIn` | `string` | `'Zoom In'` | Zoom-in control label. |
| `toolbar.labels.zoomOut` | `string` | `'Zoom Out'` | Zoom-out control label. |
| `toolbar.labels.resetZoom` | `string` | `'Reset Zoom'` | Zoom-reset control label and visible text. |
| `toolbar.labels.downloadSvg` | `string` | `'Download SVG'` | Reserved label for the SVG download control tracked in issue #91. |

These are global toolbar defaults. A Markdown fence can use `toolbar`, and a Vue component can use `:toolbar`, to override them for one diagram. Label objects merge property by property, so omitted labels keep their defaults; an empty string is an explicit label. Other non-string values are invalid. The built-in renderer uses each resolved label consistently for visible text, `title`, and `aria-label` where those surfaces exist.

`toolbar.title` is the toolbar title, not Mermaid `title` metadata. `downloadSvg` defines only the future control's label; this version does not add the download control or behavior.

## Expand

`expand` accepts either a boolean or an object, with intentionally different semantics: boolean `true` and `false` reset lower-priority state, while an object patches individual properties.

| Form | Meaning |
| --- | --- |
| `expand: true` | Resets lower-priority expand state to package defaults, with `enabled: true`. |
| `expand: false` | Resets lower-priority expand state to package defaults, with `enabled: false`. |
| `expand: { ... }` | Patches lower-priority state property by property. Omitting `enabled` preserves activation. |

An object does not re-enable a lower `expand: false` preset unless it explicitly sets `enabled: true`:

```ts
export default defineNuxtConfig({
  contentMermaid: {
    expand: { enabled: true, margin: 24 },
  },
})
```

| Option | Type | Default | Purpose and limits |
| --- | --- | --- | --- |
| `expand.enabled` | `boolean` | `true` | Enables expand interactions. |
| `expand.margin` | `number` | `0` | Space, in pixels, around the expanded diagram. |
| `expand.invokeOpenOn.diagramClick` | `boolean` | `true` | Opens the overlay when the diagram is clicked. |
| `expand.invokeCloseOn.esc` | `boolean` | `true` | Allows Escape to close the overlay. |
| `expand.invokeCloseOn.wheel` | `boolean` | `true` | Allows a wheel action on the overlay to close it. |
| `expand.invokeCloseOn.swipe` | `boolean` | `true` | Allows a one-finger swipe to close it. |
| `expand.invokeCloseOn.overlayClick` | `boolean` | `true` | Allows clicking the overlay background to close it. |
| `expand.invokeCloseOn.closeButtonClick` | `boolean` | `true` | Shows and enables the close control. |

See [Interactions](/advanced/interactions) for the full control and gesture map.

## Mermaid-owned configuration

`loader.init`, Page Mermaid Config, Direct Mermaid Config, Mermaid YAML frontmatter, and directives can carry Mermaid configuration. This package preserves that open payload but does not redefine Mermaid's options, themes, security settings, or directive semantics. Consult the official [Mermaid configuration documentation](https://mermaid.js.org/config/configuration.html) and [directive documentation](https://mermaid.js.org/config/directives.html) for that schema.
