# 自訂渲染

只有在您想擁有整個圖表體驗時才使用 custom renderer。若只需要外圍版面、共用載入 UI 或錯誤呈現，請改為包裝 `<Mermaid>`，保留內建 renderer。

## 了解 renderer 選擇

將 `components.renderer` 設為 `~/components` 中元件的名稱：

```ts
export default defineNuxtConfig({
  contentMermaid: {
    components: {
      renderer: 'CustomMermaid',
      spinner: 'MermaidSpinner',
    },
  },
})
```

設定的名稱是 Custom Renderer Candidate。用戶端上，套件會遞迴搜尋 `~/components`，找出相符檔名；比對會忽略大小寫、空格、底線、連字號、路徑區段與選用的 `.vue` 副檔名。

| 解析結果 | Rendering Owner |
| --- | --- |
| 沒有 renderer 名稱 | Built-in Renderer。 |
| Candidate 載入中 | 尚未有 renderer；預設原始碼 fallback 保持可見。 |
| Candidate 解析成功 | Custom Renderer，且獨占所有權。 |
| 找不到 Candidate 或載入失敗 | 顯示 console diagnostic 後使用 Built-in Renderer。 |

對每個已解析的 candidate，這是單向的所有權選擇。之後 Custom Renderer 若 mount 或 render 失敗，不會再觸發第二次 built-in fallback。它的 loading、error UI、theme decisions、Mermaid invocation、toolbar、fullscreen、expand 與 accessibility 行為都必須由您實作。

## 實作完整的 custom renderer

解析成功的 Custom Renderer 只會收到以下 extension inputs：

- `code`：呼叫端傳入時，已解碼的 Mermaid 原始碼。
- `spinner`：設定的 spinner 元件，或套件的 spinner fallback。
- 預設 slot：由 `<Mermaid>` 提供的原始碼 fallback。

它不會收到內建的 `pageConfig`、direct `config`、toolbar 選項、loading slots、error slots、自動主題解析或 `components.error`。請明確擁有這些關切點：

```vue
<!-- components/CustomMermaid.vue -->
<script setup lang="ts">
import { onMounted, ref, shallowRef, useId } from 'vue'
import type { Component } from 'vue'

const props = defineProps<{
  code?: string
  spinner: Component | string
}>()

const loading = ref(true)
const error = shallowRef<unknown>()
const svg = ref('')
const renderId = `custom-mermaid-${useId().replaceAll(':', '')}`

onMounted(async () => {
  try {
    const mermaid = await useNuxtApp().$mermaid()
    svg.value = (await mermaid.render(renderId, props.code ?? '')).svg
  }
  catch (cause) {
    error.value = cause
  }
  finally {
    loading.value = false
  }
})
</script>

<template>
  <section class="custom-mermaid">
    <component :is="props.spinner" v-if="loading" />
    <p v-else-if="error" role="alert">
      Diagram failed: {{ error instanceof Error ? error.message : String(error) }}
    </p>
    <div v-else v-html="svg" />
  </section>
</template>
```

此範例刻意自行擁有失敗呈現。若 renderer 需要主題變更或 Mermaid 設定，請提供並回應自己的 application-level state，而不要期待內建 renderer 的 props。

## 改為包裝內建 renderer

不要把這個 wrapper 設為 `components.renderer`。它是一般的應用程式元件：在加入呈現外觀時，仍保留內建的設定、互動、載入與錯誤行為：

```vue
<!-- components/DiagramCard.vue -->
<script setup lang="ts">
const props = defineProps<{
  title: string
  source: string
}>()

const encodedSource = computed(() => encodeURIComponent(props.source))
</script>

<template>
  <section class="diagram-card">
    <h2>{{ title }}</h2>
    <Mermaid :code="encodedSource">
      <template #loading>
        <p aria-live="polite">正在渲染圖表…</p>
      </template>
      <template #error="{ error, source }">
        <p role="alert">
          Render failed: {{ error instanceof Error ? error.message : String(error) }}
        </p>
        <details>
          <summary>顯示 Mermaid 原始碼</summary>
          <pre><code>{{ source }}</code></pre>
        </details>
      </template>
    </Mermaid>
  </section>
</template>
```

若 Nuxt 設定未 auto-import Vue utilities，請加入 `import { computed } from 'vue'`。內建 renderer 接受預設 slot 作為原始碼 fallback、`#loading` 作為初始 loading state，以及 `#error="{ error, source }"` 作為 Mermaid render failure。或者可由 `components.error` 提供全域內建 error component，並接收 `error` 與 `source`；Custom Renderer 不會使用它。

## 避免遞迴 renderer 選擇

絕對不要在設定為 `components.renderer` 的元件中渲染 `<Mermaid>`。巢狀元件會重複 candidate 選擇，可能無限遞迴。請改為呼叫 `useNuxtApp().$mermaid()`、另一個 renderer，或獨立的較低層實作。只有未被設定為 custom renderer 的 wrapper 才是安全的。
